# 新项目接入指南（从零开始）

> 适用对象：**全新项目**。要改造已有的 qygl / wygl，请看 [迁移指南.md](迁移指南.md)。
> 目标：一个新项目从空目录到「登录 + 系统管理 + 操作日志 + 账号区」全部跑通，只做三件事——**装包、注入配置、写自己的业务**。

---

## 一、3 分钟理解这两个包

| 包 | 运行端 | 提供什么 | 不提供什么（你的业务代码） |
|---|---|---|---|
| `@panweippc/auth-kit` | 后端 Node | JWT 签发/校验/无感轮换、bcrypt 密码、SVG 验证码、鉴权中间件、操作日志写入、安全告警 | 用户表、登录路由、角色权限、任何业务接口 |
| `@panweippc/admin-ui` | 前端 Vue3 | 登录页/账号区/通用 CRUD/操作日志四个**页面骨架** + 空闲检测/密码校验/401 刷新等工具 | 业务字段、接口地址、菜单路由、业务页面内容 |

**核心设计：零业务耦合。** 包里不出现 `users`/`sys_user`/`resident_owner` 等表名，不出现"业主/总经理"等角色，不写死项目名和配色。所有项目相关信息都通过 **config 对象 / 回调** 注入。

> ⚠️ 重要认知：这两个包是**骨架和工具**，不是"装上去就有一个完整后台"。它们帮你省掉的是每个项目都要重复写的认证链路和后台页面骨架；你的业务表、业务接口、业务页面仍要自己写。

---

## 二、接入总览

```
新项目
 ├─ 后端：装 auth-kit
 │   ├─ createSecurity()        → JWT 工具（填密钥）
 │   ├─ createCaptcha()         → 验证码（默认内存存储）
 │   ├─ createRequireAuth()     → 鉴权中间件（注入查用户回调）
 │   ├─ createAudit()           → 操作日志（注入表名/列名映射）
 │   └─ createSecurityAlert()   → 安全告警（注入日志目录）
 └─ 前端：装 admin-ui
     ├─ 工具：installAuthInterceptors / installFetchToken / startIdleDetector
     ├─ LoginPanel        → 登录页（填品牌 + 接口）
     ├─ AccountDropdown   → 账号区（填菜单项）
     ├─ CrudPanel         → 系统管理（填列/字段/接口）
     └─ OperationLogPanel → 操作日志（填列/接口）
```

**步骤清单**：① 安装 → ② 后端接线 → ③ 前端接线 → ④ 验证。下面逐条展开，所有代码均可直接复制到 [`examples/starter/`](../examples/starter/) 对应文件。

## 三、第 0 步：安装

### 3.1 前端 peer 依赖（两个项目都要）

后端包自带依赖（bcryptjs / jsonwebtoken / dotenv）；前端包把 Vue/Element Plus 等声明为 peer，需项目自己装：

```bash
# 前端项目
npm i vue@^3.3 element-plus@^2.2 axios@^1 pinia@^2 @element-plus/icons-vue
```

### 3.2 引用公共包的两种方式

**方式 A — 发包后（推荐长期）**：配置 `.npmrc`

```
@panweippc:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

然后（本机需先 `npm login --registry=https://npm.pkg.github.com`，token 需 `read:packages` 权限）：

```bash
# 后端
npm i @panweippc/auth-kit
# 前端
npm i @panweippc/admin-ui
```

**方式 B — 未发包时本地引用**：用 `file:` 指向本仓库

```bash
# 后端项目 package.json
"dependencies": { "@panweippc/auth-kit": "file:../../../packages/auth-kit" }
# 前端项目 package.json
"dependencies": { "@panweippc/admin-ui": "file:../../../packages/admin-ui" }
```

> 当前两个包**尚未发布**到 GitHub Packages，走方式 B。等发包后改成方式 A，业务代码无需改动——包名一致。

### 3.3 前端 Vite 配置（关键，否则 `.vue` 加载失败）

admin-ui 以 **TS / Vue SFC 源码** 分发，由消费项目的 Vite 编译。`file:` 安装出现在 `node_modules` 里，需让 Vite 允许并排除预打包：

```ts
// vite.config.ts
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import path from 'path';

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: { '@': path.resolve(__dirname, 'src') }
  },
  server: {
    // file: 安装的包在仓库内，需加入 fs 白名单
    fs: { allow: ['..', '../../../packages/admin-ui'] }
  },
  optimizeDeps: {
    exclude: ['@panweippc/admin-ui'] // 不要让 esbuild 预打包 .vue 源码
  }
});
```

若仍遇到编译问题，可改用 alias 直连源码（绕开 node_modules）：

```ts
resolve: {
  alias: { '@panweippc/admin-ui': path.resolve(__dirname, '../../../packages/admin-ui/src/index.ts') }
}
```

## 四、第 1 步：后端接线

### 4.1 数据库最小契约

公共包**不建表**。项目至少需要两张表（字段名可与默认不同，用 `columns` 映射适配）。完整建表语句见 [`examples/starter/server/db.sql`](../examples/starter/server/db.sql)。

用户表的关键字段（用于登录与会话校验）：

| 字段 | 用途 | 说明 |
|---|---|---|
| `username` | 登录账号 | 唯一 |
| `password` | 密码哈希 | bcrypt，包提供 `hashPassword()` |
| `role` | 角色名 | 签发到 token 的 `role` 字段，供前端判定权限 |

操作日志表默认列名：`userId, username, action, module, targetId, targetName, detail, beforeValue, afterValue, ipAddress, createdAt`（`createdAt` 自动填 `NOW()`）。列名不同就用 `createAudit({ columns })` 映射。

### 4.2 接线代码（server.js 骨架）

```js
import 'dotenv/config';
import express from 'express';
import cors from 'cors';
import mysql from 'mysql2/promise';
import {
  createSecurity, createCaptcha, createRequireAuth,
  createAudit, createSecurityAlert,
  hashPassword, verifyPassword, validatePassword,
  pwdFingerprint, buildLoginPayload
} from '@panweippc/auth-kit';
import path from 'node:path';

const pool = mysql.createPool({
  host: process.env.DB_HOST || '127.0.0.1',
  port: +(process.env.DB_PORT || 3306),
  user: process.env.DB_USER || 'root',
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME
});

// ① JWT：密钥放 .env，支持无感轮换
const { signToken, verifyToken } = createSecurity({
  secret: process.env.JWT_SECRET,
  previousSecret: process.env.JWT_SECRET_PREVIOUS, // 可选
  expires: process.env.JWT_EXPIRES || '12h'
});

// ② 验证码：默认内存存储（单实例够用；多实例传 store 接 Redis）
const captcha = createCaptcha({ ttl: 5 * 60 * 1000 });

// ③ 操作日志：表名/列名与默认一致时无需 columns
const audit = createAudit({ table: 'operation_logs' });

// ④ 安全告警：logDir 必须显式传（包内 __dirname 在 node_modules 里会指错）
const alert = createSecurityAlert({
  logDir: path.join(process.cwd(), 'logs'),
  webhookUrl: process.env.ALERT_WEBHOOK_URL
});

// ⑤ 鉴权中间件：查用户回调按你的表结构写
const { requireAuth } = createRequireAuth({
  verifyToken,
  publicPaths: [
    { method: 'POST', path: '/login' },
    { method: 'GET',  path: '/captcha' },
    { method: 'GET',  path: '/health' }
  ],
  findUserByUsername: async (username) => {
    const [rows] = await pool.execute('SELECT * FROM users WHERE username = ?', [username]);
    const u = rows[0];
    if (!u) return null;
    // 返回指纹 + 会话版本 → 改密/其他设备登录后旧 token 自动失效
    return { pwdFingerprint: pwdFingerprint(u.password), tokenVersion: u.token_version || 0 };
  }
  // normalizeUsername: (u) => u.replace(/^emp_/, '')  // 需要时再开
});

const app = express();
app.use(cors());
app.use(express.json());

// —— 公开接口 ——
app.get('/api/captcha', (req, res) => {
  const { token, svg } = captcha.generate();
  res.json({ success: true, data: { token, svg } });
});

app.post('/api/login', async (req, res) => {
  const { username, password, captcha: code, captchaToken } = req.body;
  // 验证码一次性校验（错误码也会消费，防暴力破解）
  const c = captcha.verify(captchaToken, code);
  if (c === 'expired') return res.status(401).json({ success: false, message: '验证码已过期' });
  if (c === 'wrong')   return res.status(401).json({ success: false, message: '验证码错误' });

  const [rows] = await pool.execute('SELECT * FROM users WHERE username = ?', [username]);
  const user = rows[0];
  if (!user || !verifyPassword(password, user.password)) {
    alert.writeSecurityAlert({ level: 'WARN', type: 'login_fail', username, ip: req.ip });
    return res.status(401).json({ success: false, message: '账号或密码错误' });
  }
  const token = signToken(buildLoginPayload({
    id: user.id, username: user.username, password: user.password,
    roleName: user.role, tokenVersion: user.token_version || 0
  }));
  await audit.createOperationLog(pool, { userId: user.id, username: user.username, action: 'login', module: 'auth', ipAddress: req.ip });
  res.json({ success: true, data: { token, username: user.username, role: user.role } });
});

app.get('/api/health', (req, res) => res.json({ status: 'ok' }));

// —— 挂载鉴权：之后的接口都需要 token ——
app.use('/api', requireAuth);

app.get('/api/users', async (req, res) => {
  const [rows] = await pool.execute('SELECT id, username, role FROM users');
  res.json({ success: true, data: rows });
});

app.listen(3010, () => console.log('server listening on 3010'));
```

### 4.3 登录链路（理解这条链，就理解了整个包）

```
前端 LoginPanel 提交 { username, password, captcha, captchaToken }
   ↓ 后端 /api/login
① captcha.verify(token, code)          一次性校验，错误即消费
② verifyPassword(password, user.password)  bcrypt 校验
③ signToken(buildLoginPayload(user))   签发 JWT，含 pwd 指纹 + ver 会话版本
   ↓ 前端存 token
后续每个请求
   ↓ requireAuth
④ verifyToken(token)                   验签（支持新旧密钥轮换）
⑤ findUserByUsername → 比对指纹/版本  改密或异地登录后旧 token 立即 401
```

> 关键点：token 里的 `pwd`（密码前 12 位指纹）和 `ver`（tokenVersion）是**主动失效**机制。改密或踢下线时，只需改数据库里的密码或 `token_version`，无需等 token 过期。

## 五、第 2 步：前端接线

### 5.1 `main.ts`：安装工具（一次装好，全局生效）

```ts
import { createApp } from 'vue';
import ElementPlus from 'element-plus';
import 'element-plus/dist/index.css';
import axios from 'axios';
import {
  createTokenStore, installAuthInterceptors, installFetchToken, startIdleDetector
} from '@panweippc/admin-ui/utils';
import App from './App.vue';
import router from './router';

const store = createTokenStore({ access: 'token', refresh: 'refreshToken' }); // key 可自定义，避免与宿主冲突

const api = axios.create({ baseURL: '/api' });
installAuthInterceptors(api, {
  store,
  refreshUrl: '/api/refresh',      // 后端未实现刷新接口时不要开自动刷新
  onUnauthorized: () => { store.clear(); router.push('/login'); }
});
installFetchToken(store);          // 让原生 fetch('/api/...') 也自动带 token

startIdleDetector({
  timeout: 30 * 60 * 1000,
  loginPath: '/login',
  onTimeout: () => store.clear()   // 超时清理；如需断 socket 在这里加
});

createApp(App).use(router).use(ElementPlus).mount('#app');
```

### 5.2 `api.ts`：统一请求

```ts
import axios from 'axios';
export const api = axios.create({ baseURL: '/api' });

export const login = (payload: any) => api.post('/login', payload).then(r => r.data);
export const getCaptcha = async () => {
  const r = await api.get('/captcha');           // { success, data: { token, svg } }
  return { token: r.data.data.token, svg: r.data.data.svg };
};
export const getUsers = (p: { page: number; pageSize: number }) =>
  api.get('/users', { params: p }).then(r => ({ data: r.data.data, total: r.data.data.length }));
```

### 5.5 路由守卫（防止未登录访问）

```ts
// router.ts —— 极简示例
router.beforeEach((to, from, next) => {
  const publicPages = ['/login'];
  const token = localStorage.getItem('token');
  if (!publicPages.includes(to.path) && !token) return next('/login');
  next();
});
```

## 七、常见坑（都来自实际踩坑）

| 现象 | 原因 | 解决 |
|---|---|---|
| Vite 报 `.vue` 无法解析 | admin-ui 是源码分发，在 node_modules 里没被编译 | 按 3.3 配 `optimizeDeps.exclude` + `fs.allow`，或 alias 直连源码 |
| 后端启动报"生产环境必须提供 JWT secret" | 没配 `JWT_SECRET` | `.env` 填强随机密钥；生产环境故意拒绝弱密钥 |
| 安全告警日志写到奇怪目录 | `logDir` 没显式传 | 传 `path.join(process.cwd(), 'logs')`，不要用包内 `__dirname` |
| 验证码总提示"已过期" | 验证码**一次性**，错误码也消费 | 失败后重新 `GET /captcha` 刷新；这是防暴力的设计 |
| 改密后旧 token 仍可用 | token 没带 `pwd`/`ver`，或回调没返回指纹 | 用 `buildLoginPayload()` 签发；`findUserByUsername` 返回 `pwdFingerprint` |
| 操作日志列值错位 | 旧版 audit 把 `NOW()` 放到了首列 | 已修复（需更新到修复后的版本） |
| 多实例部署验证码偶尔失效 | 默认内存存储不共享 | 给 `createCaptcha({ store })` 传 Redis 适配器 |
| `formatter` 拿不到整行数据 | 旧版把 value 当 row 传 | 已修复（需更新到修复后的版本） |

## 八、工作量与维护

| 阶段 | 预计 |
|---|---|
| 后端接线（含建表、登录接口） | 0.5～1 小时 |
