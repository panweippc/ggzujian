# 公共包迁移指南（qygl / wygl → shared-pkgs）

## 背景与目标

qygl（OA）与 wygl（物业）有两套相似但不等同的认证与后台管理代码。本仓库把其中**通用部分**抽成两个包：

| 包 | 内容 | 复用方式 |
|---|---|---|
| `@panweippc/auth-kit` | JWT/密码/验证码/审计日志/鉴权中间件/安全告警 | 依赖注入，零业务耦合 |
| `@panweippc/admin-ui` | 会话/密码/空闲/农历工具 + 登录/账号区/CRUD/日志组件 | 配置驱动 + 插槽扩展 |

**不通用、留在各业务项目的部分**：qygl 的 employees/departments/emp_ 前缀/总经理角色/socket 单设备踢下线；wygl 的 resident_owner/业主中心/token_version 隔离。这些是业务语义，不应进公共包。

## 一期迁移（低风险，建议先做）

### 后端：替换内联工具

```diff
- import { signToken, verifyToken, hashPassword, validatePassword } from './utils/security.js'
+ import { createSecurity, hashPassword, validatePassword } from '@panweippc/auth-kit'
+ const { signToken, verifyToken, buildLoginPayload } = createSecurity({ secret: process.env.JWT_SECRET, previousSecret: process.env.JWT_SECRET_PREVIOUS })
```

- 验证码：用 `createCaptcha()` 替换 auth.js 内联的 `captchaStore` + `genCaptchaSvg`。
- 审计：用 `createAudit()` 替换 audit.js（注意 qygl 的 `createNotification` 留在业务项目，它依赖 notifications 表）。
- 鉴权：用 `createRequireAuth()` 替换 requireAuth.js，通过 `findUserByUsername` / `normalizeUsername` 保留各自的校验差异。

### 前端：替换纯工具

```diff
- import { startIdleDetector } from '@/utils/idle-detector'
+ import { startIdleDetector } from '@panweippc/admin-ui/utils'
```

- 密码强度：`validatePassword` / `passwordRuleHint`（qygl ChangePassword、wygl SystemManagement 两处重复代码合并）。
- 401 刷新：`installAuthInterceptors(axiosInstance, { store, refreshUrl, onUnauthorized })`。
- fetch token：`installFetchToken(store)` 替换 main.ts 里的全局 fetch 包装（marker 可配置，避免冲突）。

## 二期迁移（组件层，按项目节奏）

1. 登录页：引入 `LoginPanel`，把 qygl 的天气/公告/节日/寄语写进 `#extra` 插槽；wygl 的物业导览写进 `#brand`/`#footer`。
2. 账号区：引入 `AccountDropdown`，菜单项由各项目的角色/路由配置生成。
3. 系统管理：用 `CrudPanel` 拼各 tab；qygl 的备份 tab、wygl 的参数/部门 tab 作为自定义插槽。
4. 操作日志：引入 `OperationLogPanel`，`modules`/`actions` 从后端字典接口拉取（消除前端写死的 OA/物业枚举）。
